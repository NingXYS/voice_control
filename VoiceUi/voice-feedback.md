# 语音交互故障修复

## 停止按钮

装饰动画层及其所有子元素不参与鼠标命中测试，音量峰值时缩放也限制在小范围。控制按钮有独立叠放层。语音处于启动阶段时也允许停止，避免模型加载期间只能等待。进入运行状态后会清除过期的“正在启动”提示。

## 唤醒后没有响应

本次用户提供的实际日志显示：录音 1784 ms，声纹得分 0.3783，当前操作员阈值 0.5，原因为 `speaker_mismatch`，因此在 ASR 前被拒绝。不是本次录音时长不足，也不是力控指令执行失败。部署仍保留原来的强制声纹验证和阈值；没有自动降低阈值、启用会话免验或关闭校验。现用设备下持续不匹配时，应在现有声纹页使用现场评估/重新登记功能更新当前声音样本。

新增事件 `voice.notice`：`payload.message` 为可直接显示的中文提示，`payload.reason` 为 `speaker_mismatch`、`audio_too_short_for_sv`、`speech_level_too_low`、`asr_empty`、`speech_start_timeout` 或 `turn_failed` 等原因。声纹被拒绝、ASR 空文本和处理异常会在界面显示并尝试语音播报；拒绝状态仍不会向控制端发送调力命令。等待说话超时只提示界面，避免无人说话时循环播报。旧的 `voice.speaker` 事件也会在更新后的前端显示拒绝原因，日志包含原始 reason。

修改后刷新浏览器，并从 UI 重新启动语音，使新的 Python 运行时生效。语音识别成功但按摩接收端尚未连接时，仍应明确返回“未收到控制端确认”，不能将声纹通过等同于调力成功。
