  真正的启动原理现在是两段式：

  1. 先用 scripts/setup_voice_wake.sh:8 把运行环境装到固定目录 ~/model/lyz/
     voice_control_runtime：它创建独立 venv、装依赖、在固定 install 目录里编译
     voice_control 包。

  2. 运行时用 scripts/run_voice_wake.sh:27 启动：
      - 先清掉 Conda/Python 污染变量
      - 再把 PATH 切到固定 venv
      - source ROS Humble 和固定 overlay
      - 检查 Python 3.10、依赖导入、voice_wake_entry.py、模型文件、arecord
      - 全部通过后才 exec ros2 run voice_control voice_wake_entry.py

  所以现在的思路不是“手工在当前 shell 里凑环境”，而是“先把环境固化到一个 runtime
  root，再由启动脚本自检并拉起唤醒入口”。

  唤醒配置本身走的是 scripts/voice_runtime_config.py:1：PARAFORMER_MODEL_DIR、
  AUDIO_DEVICE 等都从环境变量读，默认值写死在模块里，启动时决定，不是跑起来以后
  再临时补。

  如果你现在要启动，直接：

  cd /home/ning/model/lyz/src/voice_control
  bash scripts/run_voice_wake.sh

  只想先验环境，不真正启动：

  bash scripts/run_voice_wake.sh --check
