## Scope
### Must have
- One interim voice-only build lane selected by `-DVOICE_CONTROL_BUILD_ROBOT_CONTROLLER=OFF`; the option defaults `ON`, so ordinary package builds retain the existing controller target.
- Durable, profile-controlled build/install/runtime roots. The current-host defaults are `${HOME}/model/lyz/voice_control_build`, `${HOME}/model/lyz/voice_control_install`, and `${HOME}/model/lyz/voice_control_runtime`; target profiles may override them without product-code edits.
- A dedicated isolated ROS-Humble-compatible CPython 3.10 venv containing every non-ROS dependency required by `voice_wake_entry.py`; this is explicitly a wake-only environment, not the keyboard/GUI environment. It is created without `--system-site-packages`. Runtime sets `PYTHONNOUSERSITE=1`, rejects Miniconda and `~/.local` import origins, and permits only the dedicated venv, paths exported by the configured ROS setup, Python standard library, and `${install_root}/lib/voice_control` for the package's declared installed modules.
- A checked-in non-secret default JSON profile, an optional external local override, an x86_64 hash-locked wake-only Python lock plus wheelhouse, an asset manifest, a stdlib-only preflight, separate one-time venv/asset/build commands, and one daily launcher command. The launcher never builds automatically. ARM64 lock/wheel availability remains `待确认` until target verification.
- Required preflight: fixed overlay, CPython 3.10/SOABI, import origins, Paraformer files, VAD file, `arecord`, configured capture alias presence, and writable temp/log locations. Enumeration does not claim that the device can be opened; a separate timeout-bounded QA launch proves opening. KWS assets are required only when `WAKE_DETECTOR_MODE=kws`. TTS assets are optional because current TTS failure is non-blocking. Dify and Ollama are informational/optional so offline local behavior can start.
- Host-native ASR/KWS/VAD/TTS. Dify and Ollama stay behind their existing HTTP boundary.
- Deliberate restoration of the documented routing contract: keyword fast routes (greeting/introduction/assembly), local deterministic reply, local deterministic action, configured healthy Dify, then Ollama fallback. Removing the outer Ollama gate is a bug fix, not a new routing architecture.
- An opt-in, fail-closed QA sink that never initializes a ROS publisher, never publishes action/assembly messages, and never launches the vendor greeting process. All real-microphone or one-shot text QA must enable it.
- Clean-source proof using a controller-filtered `git archive` plus separately provisioned, checksummed assets; the archive must exclude `src/robot_controller.cpp` before extraction and reject nested `.git`, `__pycache__`, and `*.pyc` in the deliverable/runtime asset tree. A fresh-clone alternative is forbidden because it would include the controller source.
- Separate x86_64 host and Jetson/ARM64 status. Migration is not complete until the target-side compatibility gate passes; unavailable target facts remain `待确认`.

## Verification strategy
> Zero human intervention - all verification is agent-executed.
- Test decision: TDD for new runtime/profile/preflight/launcher and routing boundaries, using Python `unittest`; shell/CMake behavior is driven by subprocess tests and clean temporary prefixes. Each task first adds or identifies a failing assertion, then implements the smallest change that makes it pass.
- Per Python task: use `/usr/bin/python3` before Todo 4 bootstrap and the profile's exact `venv_python` afterward; run `-m py_compile <changed Python files>`, then the named targeted `-m unittest ...`, then full `-m unittest` before its execution report is finalized.
- Per build task: run from `env -i HOME=/home/ning USER=ning PATH=/usr/bin:/bin bash --noprofile --norc`, source `/opt/ros/humble/setup.bash`, and use task-owned temporary build/install prefixes before touching the fixed prefix.
- Installed-overlay freshness gate: after tests for each installed product change in Todos 7, 8, 9 and 11 (and after every fix task for them), run the reviewed Todo 3 build wrapper against the fixed profile, then SHA256-compare every changed installed Python module with its source. The task cannot be approved/committed while the fixed overlay is stale; the wrapper still builds controller OFF and never runs it.
- Runtime-origin gate: run the launcher/preflight once from a clean shell and once from the current Conda-polluted shell. Both JSON reports must identify CPython 3.10 and identical allowed module origins; no origin may contain `/home/ning/miniconda3` or `/home/ning/.local`.
- Safety gate: before and after every audio/runtime QA, assert no processes matching `robot_controller|move_group|single_point_demo` and no QA path that creates a ROS command publisher. The fail-closed sink must report blocked action/demo attempts as test evidence.
- Secret gate: tests generate a random sentinel, place it only in the final Python child's `DIFY_API_KEY`, and capture stdout/stderr/config JSON in a task-owned temporary directory. Build `scan_roots` from only existing paths among `.ai/plans`, `.ai/tasks`, `.ai/runs`, `.ai/reviews`, `.omo/drafts`, `config`, and those capture files; require `rg -F -- "$SENTINEL" "${scan_roots[@]}"` to exit exactly 1. The report records that literal shell expression, never the expanded value. Configuration key names may appear; the generated value may not.
- Evidence: each execution task writes `.ai/runs/<task-slug>.execution.md` from `.ai/templates/execution-report.template.md`, including commands, exit codes, redacted outputs, changed files, and unresolved `待确认` items.
